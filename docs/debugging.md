# 已发现并修复的工程问题

## 内部服务调用的超时

检查 C++ 对 Python 的调用时发现：对同步 Beast 读写设置 `tcp_stream::expires_after`，不能按预期保证同步操作的截止时间。若 AI 容器建立连接后不响应，工作线程可能长时间被占用；8 个线程都卡住后，普通聊天请求也会排队。

修复：内部 HTTP 调用改为独立 `io_context` 上的异步 DNS、连接、写入和读取，使用一个 10 秒总期限 `steady_timer`。超时取消解析并关闭 socket；回调首先检查任务是否已结束，避免超时后的迟到回调重新开始下一步操作。

验证依据：C++ 已在 Windows 实际编译、链接，并通过真实 FastAPI 任务链路。静默不响应端点的故障注入尚未测量；可在 Windows 上用独立测试监听器接收连接后不返回数据，检查显式 AI 请求在总期限后失败并释放工作线程。没有伪造故障注入的延迟数据。

## 浏览器重试时消息 ID 必须保持不变

前端对每次新消息生成 UUID，首次提交失败后保留原消息对象。点击重试直接复用该对象，不能重新生成 UUID，否则网络丢失确认的场景会产生两条数据库记录。

验证：初版无头浏览器模拟第一次请求返回 503，再点击重试；捕获两次请求断言 `client_message_id` 相同，成功响应后只显示一个确认消息。此后 `scripts/smoke.py` 已在 Windows 真实服务验证相同 ID 相同内容返回同一消息，修改内容返回 409，并检查并发写入序号唯一。

## 来电不弹出：SQL 保留字

真实双浏览器测试中，文字、图片和录音正常，但接收方没有来电窗口。检查 C++ 错误日志发现数据库查询失败，定位到订阅初始化接口用 `AS cursor` 作为查询别名，和 MySQL 保留字冲突。改成 `event_cursor`，保持 HTTP 返回字段仍为 `cursor`，重新编译后两端完成语音连接和视频帧接收，拒接 / 挂断也通过。复现与回归脚本为 `scripts/e2e.cjs`。

## 中文目录下 MySQL 无法启动

独立 MySQL 可以初始化到项目目录，但启动时错误日志路径异常，不能可靠使用当前中文路径。将项目数据库放到 `%LOCALAPPDATA%/QingLiao/<项目路径哈希>/mysql`，与系统 MySQL80 分开，固定监听 3307。重跑初始化、真实 API、正常停止与重启均通过，系统 MySQL80 保持 Running。

## 停止服务时父进程先退出

停止 Vite 后，其 Python 包装进程会自行退出。如果停止脚本已取得旧的 Process 对象，随后再查命令行会找不到该进程，原本会错误提示无法验证进程归属。修正为在 CIM 查不到时视为已退出，仅清理 PID 文件；对于仍存在的进程继续核对可执行文件 / 命令行。实际停止与重新启动已通过。
