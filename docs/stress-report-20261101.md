## 问题与限制
1. 高并发下出现连接拒绝，尚未完成单独复现和服务端/监听队列/客户端资源归因，不标记为已修复。并发级别为客户端任务并发，不等价于持续活跃连接数。尚未通过数据库直接核验每条消息与会话序号。
2. 启动脚本后台 MySQL 出现目录不可写；直接运行隔离 MySQL 成功。中文目录试验另出现参数路径异常。尚未确定是否由受限进程启动环境导致，不认定为普通用户必现。
3. Node监听8080和18080都返回EACCES，本轮未执行浏览器UI回归；既往通过记录不代替本轮结果。
4. 尚未完成长时间浸泡、慢消费者/连接洪泛、网络丢包、磁盘耗尽、数据库中断恢复、上传与撤权竞态、同分片并发覆盖、真实跨设备音视频和TURN、真实模型服务限流测试。
5. 临时数据库路径为用户TEMP/smartchat-stress-20261101/mysql；原数据库未被清理。新增脚本及报告未推送GitHub。

这些结果只能作为首轮有界压力与功能回归，不能作为完整饱和验收或生产容量承诺。

注意：stress-concurrency-20261101.json 是客户端默认连接池限制下的初测历史数据；随后脚本已改为600连接上限。该历史文件不是当前脚本的复跑结果，不用于容量结论。

## 第二轮追加验证
- 独立复测曾在256并发全部成功、512并发40/1500连接拒绝；阈值会随运行环境波动，不能据此承诺容量。
- 增加持久化分页核验后的最新结果更新于 stress-saturation-20261101.json：128并发0错误；256并发2/1500连接拒绝。两级各500个唯一客户端消息ID最终各对应500条记录，序号无冲突，负载后健康接口正常。
- 新增 stress-slow.py：32/128/300条不完整HTTP头连接下健康请求均200，关闭后仍200。仅短时部分请求头场景，不代表完整慢消费者或超时回收验收。
- 新增 stress-upload-race.py：每操作16请求、8工作线程，对同一上传并发初始化、同分片重复写入、并发完成，返回单一ID，最终下载字节校验一致。
- 当前脚本仍基于 product-smoke 生成测试资料，只针对本机测试环境，不应对生产数据运行。连接拒绝根因与修复仍未完成；本轮不声称后端缺陷已修复。
