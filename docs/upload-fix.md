# 文件偶发发送失败修复

## 已复现的原因

Windows 服务日志出现“在多字节的目标代码页中，没有此 Unicode 字符可以映射到的字符”。同一合成文件内容、同一用户权限，普通英文、中文和部分 emoji 文件名成功，`𠮷字资料.txt` 返回 503。

原因是上传与下载 MIME 判断把网络传入的 UTF-8 文件名当作 Windows 原生文件路径，执行 `std::filesystem::path(name).extension().string()`，触发了系统代码页转换。实际文件落盘本就使用随机 ASCII ID，无需转换原文件名。

修复：原文件名仅作为 UTF-8 元数据，扩展名使用字节字符串提取和 ASCII 大小写处理；上传和下载均不再将原名交给 Windows 文件路径转换。

## 超时与确认提示

原先 C++ 用同一个 30 秒期限接收完整 HTTP 请求。现在请求头最多 15 秒，文件上传体最多 300 秒，普通请求体保持 30 秒；超过 1 MB 的响应写入期限为 300 秒。分享网关与浏览器上传总期限调整为 360 秒。单文件大小仍为 50 MB，不支持分片 / 断点续传。

前端现在等待附件消息入库确认后才提示已发送。文件已上传、但消息发送失败时，提示点击失败消息重试，复用原文件 ID 和消息 ID，无需重新上传。

## 实际回归验证

2026-10-28，使用合成资料，修复后的 Windows 本机和真实公网 HTTPS 网关均通过以下名称的上传、下载字节比对及附件消息发送：

- `plain.txt`
- `中文资料.txt`
- `报告😀.txt`
- `𠮷字资料.txt`
- `file space + # %.bin`
- `相册🚀.PNG`（额外验证 MIME 判断）

本机以每秒 1024 字节发送 35840 字节，持续 35 秒，超过原 30 秒期限后仍返回 200。并重跑 WebSocket 鉴权 / 实时消息 / 补拉以及扩展接口检查，均通过。

复现脚本：

```powershell
.\.venv\Scripts\python.exe scripts/upload-regression.py --slow
.\.venv\Scripts\python.exe scripts/upload-regression.py --share
```

公网链路仍可能受网络中断或平台限制影响，回归测试不等于保证任何网络下的任意文件均成功。大于 50 MB 或空文件会被明确拒绝。
